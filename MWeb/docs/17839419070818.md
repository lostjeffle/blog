## FUSE - Feature - uring - buffer pool

### pool buffer

传统的 fuse io-uring 机制中，每个 ring entry (struct fuse_ring_ent) 都必须分配并绑定一个 payload buffer，即注册 N 个 ring entry 就要预先分配 N 个 payload buffer，而且每个都必须按最大 payload size 来分配。考虑到：

- lookup / open 这类请求实际数据量远小于上限；
- unlink / fsync 这类请求根本不需要 payload。

因而上述设计会导致 payload buffer 内存的利用率很低。为了解决上述问题，为 fuse io-uring 模式引入 payload buffer pool，ring entry 和 payload buffer 不再是一一映射的关系，而是 ring entry 在处理请求（例如 FUSE_READ/FUSE_WRITE） 的时候为 ring entry 按需地分配 payload buffer


#### negotiation

此时 FUSE 协商过程中，引入 FUSE_HAS_IO_URING_BUFPOOL 标志来开启 (payload) buffer pool 功能

```c
#define FUSE_HAS_IO_URING_BUFPOOL (1ULL << 43)
```


#### server: ring setup

此时 FUSE server 在注册 ring entry 的时候，每个 io_uring 实例（queue）下发的第一个 FUSE_URING_REQ_REGISTER cmd 的 struct fuse_uring_cmd_req 来描述这个 queue 的 buffer pool

```c
struct fuse_uring_cmd_req {
    ...
    uint32_t flags;        /* 置 FUSE_URING_BUFPOOL 启用 buffer pool */

    struct {
            uint32_t buf_size;  /* 每块 buffer 的尺寸 */
            uint16_t nr_bufs;   /* buffer 数量 */
    } init;
};
```

```c
/* fuse_uring_cmd_req flags */
#define FUSE_URING_BUFPOOL		(1 << 0)
```

- @flags 必须置上 FUSE_URING_BUFPOOL 以描述开启 buffer pool
- 此时 FUSE server 需要为整个 queue 分配一整块连续的内存作为整个 queue 的 (payload) buffer pool，此时第一个 FUSE_URING_REQ_REGISTER cmd 描述的
    - payload buffer 即描述这一整块内存 (对应 sqe.addr 指向一个 iovec 数组，iovec[0] 描述 header buffer, iovec[1] 就描述这一整块内存)
    - @init.buf_size 描述这个 (payload) buffer pool 中每个 payload buffer 的大小
    - @init.nr_bufs 描述这个 (payload) buffer pool 中的 payload buffer 的数量

> 首个 FUSE_URING_REQ_REGISTER cmd 后面的所有 FUSE_URING_REQ_REGISTER cmd，其 fuse_uring_cmd_req.flags 也都必须置上 FUSE_URING_BUFPOOL，但是其 iovec[1] 可以不必设置


此时内核侧通过循环缓冲区 (struct fuse_bufpool) 的方式管理 (payload) buffer pool，其中 struct fuse_bufpool_buf 描述一个 payload buffer

```c
struct fuse_bufpool {
    u32 nbufs;                    /* 总容量 = nr_bufs */
    u32 head;                     /* 分配指针 */
    u32 tail;                     /* 回收指针 */
    struct fuse_bufpool_buf bufs[];/* 环形数组 */
};
```

```c
struct fuse_bufpool_buf {
    void  *addr;   /* 用户态地址 */
    size_t len;    /* 长度（= buf_size） */
    u16    id;     /* 这个缓存在整个循环缓冲区中的 index */
};
```

- @head 描述分配缓存时，下一个可用于分配的缓存，即分配缓存的时候就是将 `buf = bufs[head % nbufs]; head++`
- @tail 描述释放缓存时，将释放的缓存放置在哪个位置，即释放缓存的时候就是将 `bufs[tail % nbufs] = buf; tail++`
- full:   tail - head >= nbufs
- buffer pool 刚初始化完成的时候，`head = 0; tail = nbufs;` 因而 buffer pool 刚初始化完成的时候就处于 full 的状态
- empty:  tail == head

```
fuse_uring_register
    # for first FUSE_URING_REQ_REGISTER cmd:
        fuse_uring_create_queue
            # if cmd_req->flags & FUSE_URING_BUFPOOL:
                fuse_uring_bufpool_setup
                    # alloc 'struct fuse_bufpool_buf' with 'struct fuse_bufpool_buf bufs[]' array
                    # init each 'struct fuse_bufpool_buf' in pool.bufs[] array
                    
                    # when buffer pool init completion:
                    pool->nbufs = nr_bufs;
                    pool->tail = nr_bufs;
                    pool->head = 0
```


#### send request: alloc buffer

此时在请求发送过程中，会为 ring entry 动态地从 buffer pool 中分配 payload buffer，保存在 ent->buf 字段

```c
    struct fuse_ring_ent {
        ...
        union {
                void *payload;                 /* 旧：绑定的 payload buffer */
                struct fuse_bufpool_buf buf;   /* 新：从池中借来的 buffer */
        };
    };
```

```
fuse_simple_request
    __fuse_request_send
        fuse_send_one(fiq, req)
            fiq->ops->send_req(fiq, req), i.e. fuse_uring_queue_fuse_req()
                # get the first entry (fuse_ring_ent) in queue->ent_avail_queue list
                
                fuse_uring_prep_buffer(ent, req)
                    # if fuse_uring_req_has_payload(req):
                        fuse_uring_select_buffer(ent)
                            buf = &pool->bufs[head % pool->nbufs]
                            pool->head++
                            ent->payload_buf = *buf
                
                fuse_uring_add_req_to_ring_ent(ent, req)
                    ...
                
                fuse_uring_dispatch_ent(ent)
                    # schedule uring worker (**the uring worker context**)
                        fuse_uring_send_in_task
                            fuse_uring_prepare_send(ent, req)
                                fuse_uring_args_to_ring
                                    ent_in_out.buf_id = ent->payload_buf.id
                            fuse_uring_send(ent, ...)
```

同时 header buffer 中的 ent_in_out.buf_id 字段用于告诉 FUSE server 这个请求当前绑定的 buffer 在 buffer pool 中的位置；FUSE server 通过 ent_in_out.buf_id 就可以定位到这个请求对应的 payload buffer

### registered buffer pool

请求发送过程中为了满足 FR_LOCKED 语义要求的 "在持有 FR_LOCKED 锁的时候不能发生阻塞" 语义，在 memcpy (持有 FR_LOCKED) 过程中不能发生缺页，因而在每次 memcpy 之前需要对 FUSE server 传入的用户态缓存执行 FOLL_GET get_user_pages_*() 操作，以确保用户态缓存都已经 fault in 了，从而防止后续 memcpy 过程中发生缺页

```c
/*
 * Lock the request.  Up to the next unlock_request() there mustn't be
 * anything that could cause a page-fault.  If the request was already
 * aborted bail out.
 */
static int lock_request(struct fuse_req *req)
```

```
fuse_simple_request
    __fuse_request_send
        fuse_send_one(fiq, req)
            fiq->ops->send_req(fiq, req), i.e. fuse_uring_queue_fuse_req()

                # get the first entry (fuse_ring_ent) in queue->ent_avail_queue list
                fuse_uring_add_req_to_ring_ent(ent, req)
                
                fuse_uring_dispatch_ent(ent)
                    # schedule uring worker (**the uring worker context**)
                        fuse_uring_send_in_task
                            fuse_uring_prepare_send(ent, req)
                                fuse_uring_copy_to_ring
                                    fuse_uring_args_to_ring
                                        fuse_copy_args
                                            fuse_copy_folios
                                                fuse_copy_folio
                                                    fuse_copy_fill
                                                        # without FR_LOCKED, page fault is permitted
                                                        iov_iter_get_pages2
                                                            gup_flags = 0
                                                            get_user_pages_fast(..., gup_flags, ...)
                                                        
                                                        lock_request # with FR_LOCKED
                                                    
                                                    mapaddr = kmap_local_folio()
                                                    # memcpy with FR_LOCKED
                                                    
                                                    # upon the next fuse_copy_fill()
                                                    fuse_copy_fill
                                                        unlock_request # release FR_LOCKED                                  
```

这样对于 io-uring 模式下的 payload buffer，即使对于相同 payload buffer，每处理一个请求都会触发一次 FOLL_GET get_user_pages_*() 操作

为了解决这一问题，在上述 buffer pool 模式的基础上，引入 registered buffer pool 模式


#### negotiation

registered buffer pool 依赖 buffer pool 模式，因而 FUSE 协商过程中，必须开启 FUSE_HAS_IO_URING_BUFPOOL 标志


#### server: register buffer

在注册 ring entry 之前，FUSE server 需要通过 IORING_REGISTER_BUFFERS io_uring_register() 来注册一组 fixed payload buffer

[title:'io_uring - Feature - Fixed Buffer'](mweblib://16019669100887)

IORING_REGISTER_BUFFERS io_uring_register() 中就会对传入的 fixed user buffer 执行 FOLL_PIN|FOLL_LONGTERM pin_user_pages*()

```
io_uring_register
    # opcode IORING_REGISTER_BUFFERS:
    io_sqe_buffers_register
        # for each iovec
            io_sqe_buffer_register
                # pin user pages of this registered user buffer (fixed buffer)
                pin_user_pages(..., FOLL_WRITE | FOLL_LONGTERM, ...)
                    gup_flags |= FOLL_PIN
```

#### server: ring setup

之后 FUSE server 在注册 ring entry 的时候，FUSE_URING_REQ_REGISTER cmd 的 struct fuse_uring_cmd_req 的 @flags 字段必须置上 FUSE_URING_BUFPOOL|FUSE_URING_REGISTERED_BUFFERS 以描述这个 ring entry 使用了 fixed buffer 

```c
struct fuse_uring_cmd_req {
    ...
    uint32_t flags;        /* 置 FUSE_URING_BUFPOOL 启用 buffer pool */
};
```

```c
/* fuse_uring_cmd_req flags */
#define FUSE_URING_BUFPOOL		(1 << 0)
#define FUSE_URING_REGISTERED_BUFFERS   (1 << 1)
```

#### send request

后续在发送请求的时候，和 buffer pool 模式一样，从 buffer pool 中为当前 uring entry 分配一个 register payload buffer，之后需要初始化 payload buffer 对应的 iov_iter 结构；对于非 registered fixed payload buffer 的情况，这个 iov_iter 都是 ITER_IOVEC 类型，而对于 registered fixed payload buffer，对应的 iov_iter 则都是 ITER_BVEC 类型的

```
setup_fuse_copy_state
    # for registered fixed payload buffer:
        io_uring_cmd_import_fixed(..., iter, ...)
            io_import_fixed
                iov_iter_bvec(iter, ...)
                    iter.iter_type = ITER_BVEC
```

这样后续在请求传输过程中，fuse_copy_fill() 过程中仍然会对 iov_iter 调用 iov_iter_get_pages2(iter, ...)，但由于此时传入的 iter 是 ITER_BVEC 类型的，这里就不会再执行 FOLL_GET get_user_pages_*() 操作

```
fuse_simple_request
    __fuse_request_send
        fuse_send_one(fiq, req)
            fiq->ops->send_req(fiq, req), i.e. fuse_uring_queue_fuse_req()

                fuse_uring_dispatch_ent(ent)

                        fuse_uring_send_in_task(..., issue_flags)
                            fuse_uring_prepare_send(ent, req, issue_flags)
                                fuse_uring_copy_to_ring(..., issue_flags)
                                    fuse_uring_args_to_ring(..., issue_flags)
                                        fuse_copy_args
                                            fuse_copy_folios
                                                fuse_copy_folio
                                                    fuse_copy_fill
                                                        # without FR_LOCKED, page fault is permitted
                                                        iov_iter_get_pages2(iter, ...)
                                                            # for ITER_BVEC tye iov_iter:
                                                            # no get_user_pages_fast() calling
                                                                           
```


### zero-copy

#### negotiation

zero-copy 依赖 buffer pool 模式，因而 FUSE 协商过程中，必须开启 FUSE_HAS_IO_URING_BUFPOOL 标志


#### server: register buffer

在注册 ring entry 之前，FUSE server 需要通过 IORING_REGISTER_PBUF_RING io_uring_register() 来注册 kernel-managed payload buffer (kmbuf) 描述符的 pool

```c
struct io_uring_buf_reg {
	__u64	ring_addr;
	__u32	ring_entries;    // .ring_entries = N (queue slots)
	__u16	bgid;
	__u16	flags;    // .flags = IOU_PBUF_RING_MMAP | IOU_PBUF_RING_KERNEL_MANAGED
	__u64	resv[3];
};
```

IORING_REGISTER_BUFFERS io_uring_register() 中就会对传入的 fixed user buffer 执行 FOLL_PIN|FOLL_LONGTERM pin_user_pages*()

```
# IORING_REGISTER_PBUF_RING
io_uring_register
    io_register_pbuf_ring
        io_alloc_pbuf_ring
            # allocate ring_entries slots (struct io_uring_buf_ring)
```

之后 FUSE server 通过对 io_uring fd mmap(2) 的方式来访问这一块 kmbuf 描述符循环缓冲区


#### server: ring setup

之后 FUSE server 在注册 ring entry 的时候

- FUSE_URING_REQ_REGISTER cmd 的 struct fuse_uring_cmd_req 的 @flags 字段必须置上 FUSE_URING_BUFPOOL|FUSE_URING_REGISTERED_BUFFERS|FUSE_URING_ZERO_COPY 以描述这个 ring entry 使用了 zero-copy 
- init.zero_copy_index 描述当前 uring entry 使用的 kmbuf 描述符在之前注册的 kmbuf 描述符循环缓冲区中的位置

```c
struct fuse_uring_cmd_req {
    ...
    uint32_t flags;        /* 置 FUSE_URING_BUFPOOL 启用 buffer pool */
    struct {
            ...
            uint16_t zero_copy_index;
    } init;
};
```

```c
/* fuse_uring_cmd_req flags */
#define FUSE_URING_BUFPOOL		(1 << 0)
#define FUSE_URING_REGISTERED_BUFFERS   (1 << 1)
#define FUSE_URING_ZERO_COPY	           (1 << 2)
```

#### server: handle request

FUSE server 在接收到 CQE 的时候

- 发现 header buffer 中的ent_in_out.flags 设置有 FUSE_URING_ENT_ZERO_COPY 知道这个请求是 zero-copy  模式的；
- 同时 header buffer 中的 ent_in_out.buf_id 字段用于告诉 FUSE server 这个请求当前绑定的 kmbuf 描述符在之前注册的 kmbuf 描述符循环缓冲区中的位置

```c
/* FUSE_URING_ENT_ZERO_COPY: Set if the ent's payload is zero-copied */
#define FUSE_URING_ENT_ZERO_COPY  (1 << 0)
```

例如 FUSE server 在接收到 FUSE_WRITE 请求，需要将数据写入 backing fd，这个时候会发起一个 IORING_OP_WRITE_FIXED sqe，这里面内核会根据之前 ent_in_out.buf_id 字段定位到对应内核中的 kmbuf (及 bvecs 数组)，之后就调用 backing fd 的 read_iter()/write_iter() 对 backing fd 执行读写操作，其中这个 kmbuf 就作为这次读写的目标内存缓冲区
