## FUSE - Feature - Passthrough


### API routine

#### open: FUSE_DEV_IOC_BACKING_OPEN ioctl

FUSE server 在处理 FUSE_OPEN 请求的时候，需要执行 FUSE_DEV_IOC_BACKING_OPEN ioctl，向内核注册 backing file fd

```
struct fuse_backing_map map;
ioctl(devfd, FUSE_DEV_IOC_BACKING_OPEN, &map);
```


```c
struct fuse_backing_map {
	int32_t		fd;
	uint32_t	flags;
	uint64_t	padding;
};
```

@fd 即为 backing file fd，@flags、@padding 字段目前都是 reserved 未使用的


将 struct fuse_backing_map 转换为对应的 struct fuse_backing 结构

```c
/** Container for data related to mapping to backing file */
struct fuse_backing {
	struct file *file;
	struct cred *cred;

	/** refcount */
	refcount_t count;
	struct rcu_head rcu;
};
```

并将这个 fuse_backing 结构注册到每个 fc 维护的 idr 树中，这个 idr 树管理所有的 struct fuse_backing 结构

```c
struct fuse_conn {
#ifdef CONFIG_FUSE_PASSTHROUGH
	/** IDR for backing files ids */
	struct idr backing_files_map;
#endif
}
```

FUSE_DEV_IOC_BACKING_OPEN ioctl 返回当前这个注册的 struct fuse_backing 结构在 idr 中的编号，后续就可以用这个编号来唯一标识这个注册的 fuse_backing 结构


#### open: reply with fuse_open_out

FUSE server 在返回 FUSE_OPEN reply 的时候，需要：
- 在 open reply 返回的 open_flags 带上 FOPEN_PASSTHROUGH 标记
- 在 open reply 里带上之前 FUSE_DEV_IOC_BACKING_OPEN ioctl 的返回值即 backing_id

```
struct fuse_open_out {
	uint64_t	fh;
	uint32_t	open_flags;
	int32_t		backing_id;
};
```


在开启 passthrough 时，每个 fuse_file 会分配一个对应的 struct backing_file (@passthrough 字段)

```c
struct fuse_file {
#ifdef CONFIG_FUSE_PASSTHROUGH
	/** Reference to backing file in passthrough mode */
	struct file *passthrough;
	const struct cred *cred;
#endif
}
```

struct backing_file 其实是 struct file 的一个封装

- backing_file.file.f_path 描述 backing 文件的路径，其实就来自于 FUSE_DEV_IOC_BACKING_OPEN ioctl 时注册的 backing_map.fd
- backing_file.user_path 描述 fuse 文件的路径

```c
/* Container for backing file with optional user path */
struct backing_file {
	struct file file;
	union {
		struct path user_path;
		freeptr_t bf_freeptr;
	};
};
```

而之前通过 FUSE_DEV_IOC_BACKING_OPEN ioctl 注册的 struct fuse_backing 则是 per-fuse_inode 的

```c
struct fuse_inode {
#ifdef CONFIG_FUSE_PASSTHROUGH
	/** Reference to backing file in passthrough mode */
	struct fuse_backing *fb;
#endif
}
```

内核在接收到这个 open reply 的时候，就
- 根据 open reply 返回的 backing fd 在 IDR 树中找到对应的 struct fuse_backing
- 根据 struct fuse_backing 为当前的 fuse_file 创建对应的 backing_file，并保存在 ff->passthrough 字段
- 将找到的 struct fuse_backing 保存在 fi->fb 字段

```sh
f_ops->open(), i.e. fuse_open
    fuse_open_common
        fuse_do_open
            fuse_file_open
                fuse_send_open // send FUSE_OPEN request
                ff->open_flags = outarg.open_flags;
        
        fuse_finish_open
            fuse_file_io_open
                # passtrhough open (without FOPEN_PASSTHROUGH):
                fuse_file_passthrough_open
                    fuse_passthrough_open
                        # find struct fuse_backing with given backing_id in IDR tree
                        
                        # allocate bacing file (struct file*)
                        ff->passthrough = backing_file
                        ff->cred = get_cred(fb->cred)
                    
                    fuse_file_uncached_io_open
                        fi->iocachectr--
                        ff->iomode = IOM_UNCACHED
                        fi->fb = fuse_backing
```


#### read

之后对 FUSE 文件的 read(2) 操作就会直接转化为对 backing 文件的 read(2) 操作（使用 FUSE server 的文件权限）

```
fuse_file_read_iter
    # for passthrough:
    fuse_passthrough_read_iter
        backing_file = ff->passthrough
        backing_file_read_iter(backing_file, ..., ff->cred)
            # read backing_file directly with FUSE server's credential
            vfs_iter_read(backing_file)
            
            ->accessed(), i.e. fuse_file_accessed()
                # invalidate atime
```


#### write

之后对 FUSE 文件的 write(2) 操作就会直接转化为对 backing 文件的 write(2) 操作（使用 FUSE server 的文件权限）

```
fuse_file_write_iter
    # for passthrough:
    fuse_passthrough_write_iter
        backing_file = ff->passthrough
        backing_file_read_iter(backing_file, ..., ff->cred)
            # write backing_file directly with FUSE server's credential
            vfs_iter_write(backing_file)
            
            ->end_write(), i.e. fuse_passthrough_end_write()
                # update fuse inode's size
                fuse_write_update_attr
```


#### mmap

之后对 FUSE 文件的 mmap(2) 操作就会直接转化为对 backing 文件的 mmap(2) 操作（使用 FUSE server 的文件权限）

```
fuse_file_mmap
    # for passthrough:
    fuse_passthrough_mmap
        backing_file = ff->passthrough
        backing_file_mmap(backing_file, ..., ff->cred)
            # mmap backing_file directly with FUSE server's credential
            backing_file->->f_op->mmap()
            
            ->accessed(), i.e. fuse_file_accessed()
                # invalidate atime
```

#### close

passthrough 打开的文件执行 close(2) 或者 unmap 的时候，在触发 fuse_file release 操作的时候，就会释放 backing_file，并减小 fi->iocachectr 计数；当 fi->iocachectr 计数减为 0 即所有 passthrough open 的文件都已经关闭时，就将 fi->fb 重设为 NULL

```
# close(2)
____fput
    fuse_release
        fuse_prepare_release
            # for passthrough:
            fuse_passthrough_release
                fput(ff->passthrough) # free backing_file
                ff->passthrough = NULL
        
        fuse_file_put(ff)
            # normally it's last put:
                fuse_file_io_release
                    case IOM_UNCACHED:
                        ff->iomode = IOM_NONE;
                        fi->iocachectr++;
                        if (fi->iocachectr == 0)
                            fi->fb = NULL
                            
                # send FUSE_RELEASE
                # free fuse_file (ff)
```


### constraint

#### FOPEN_PASSTHROUGH ❌ non-FOPEN_PASSTHROUGH

对于同一个文件，passthrough 模式不能与非 passthrough 模式混用，即一旦一个文件 open(2) 的时候 FUSE server 返回了 FOPEN_PASSTHROUGH，那么同一个文件后续 open(2) 的时候也必须带上 FOPEN_PASSTHROUGH，否则当前 open(2) 操作就会返回 -EIO；除非之前通过 FOPEN_PASSTHROUGH 打开的文件都已经 close 了

```sh
# non-FOPEN_DIRECT_IO open
f_ops->open(), i.e. fuse_open
    fuse_open_common
        fuse_do_open
            fuse_file_open
                fuse_send_open // send FUSE_OPEN request
                ff->open_flags = outarg.open_flags;
        
        fuse_finish_open
            fuse_file_io_open
                # if fi->fb exists (i.e. file is in passthrough mode)
                # but current ff->open_flags has no FOPEN_PASSTHROUGH:
    
            	/*
            	 * The file open mode determines the inode io mode.
            	 * Using incorrect open mode is a server mistake, which results in
            	 * user visible failure of open() with EIO error.
            	 */        
                return -EIO
```


#### FOPEN_PASSTHROUGH ❌ cached mode

如果一个文件事先处于 cached 模式（non-FOPEN_DIRECT_IO open 或者是 FOPEN_DIRECT_IO+DIRECT_IO_ALLOW_MMAP mmap），那么后续对同一个文件的 FOPEN_PASSTHROUGH open 会返回 -EIO

```sh
# non-FOPEN_DIRECT_IO open
f_ops->open(), i.e. fuse_open
    fuse_open_common
        fuse_do_open
            fuse_file_open
                fuse_send_open // send FUSE_OPEN request
                ff->open_flags = outarg.open_flags;
        
        fuse_finish_open
            fuse_file_io_open
                # passtrhough open (without FOPEN_PASSTHROUGH):
                fuse_file_passthrough_open
                    fuse_passthrough_open
                        # find struct fuse_backing with given backing_id in IDR tree
                        
                        # allocate bacing file (struct file*)
                        ff->passthrough = backing_file
                        ff->cred = get_cred(fb->cred)
                    
                    fuse_file_uncached_io_open
                        # if fi->iocachectr > 0:
                            return -ETXTBSY

            	/*
            	 * The file open mode determines the inode io mode.
            	 * Using incorrect open mode is a server mistake, which results in
            	 * user visible failure of open() with EIO error.
            	 */        
                return -EIO
```


#### FOPEN_PASSTHROUGH ✅ FOPEN_DIRECT_IO

passthrough 模式可以与 FOPEN_DIRECT_IO 复用

> Opening a new file with FOPEN_DIRECT_IO for an inode that is already open for passthrough is allowed, but only if the FOPEN_PASSTHROUGH flag and correct backing file id are specified as well.
> 
> The read/write IO of such files will not use passthrough operations to the backing file, but mmap, which does not support direct_io, will use the backing file insead of using the page cache as it always did.

此时表示 READ/WRITE 请求**直接**发送给 FUSE server 处理，但是 mmap(2) 操作还是直接转化为对 backing 文件的 mmap(2) 操作

此时 open(2) 的时候

```sh
f_ops->open(), i.e. fuse_open
    fuse_open_common
        fuse_do_open
            fuse_file_open
                fuse_send_open // send FUSE_OPEN request
                ff->open_flags = outarg.open_flags;
        
        fuse_finish_open
            fuse_file_io_open
                # passtrhough open (without FOPEN_PASSTHROUGH):
                fuse_file_passthrough_open
                    fuse_passthrough_open
                        # find struct fuse_backing with given backing_id in IDR tree
                        
                        # allocate bacing file (struct file*)
                        ff->passthrough = backing_file
                        ff->cred = get_cred(fb->cred)
                    
                    fuse_file_uncached_io_open
                        fi->iocachectr--
                        ff->iomode = IOM_UNCACHED
                        fi->fb = fuse_backing
```
