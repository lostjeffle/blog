## FUSE - IO - IO Modes


### background

FUSE iomode 的引入是为了解决 DIRECT_IO_ALLOW_MMAP 与 (FOPEN_DIRECT_IO) parallel direct writes 优化 ([title:'FUSE - IO - Direct IO'](mweblib://16738553480877#parallel-direct-write-optimization)) 两者的兼容性问题

cb098dd24bab fuse: introduce inode io modes
205c1d802683 fuse: allow parallel dio writes with FUSE_DIRECT_IO_ALLOW_MMAP


问题背景见 https://lore.kernel.org/all/CAOQ4uxh6RpoyZ051fQLKNHnXfypoGsPO9szU0cR6Va+NR_JELw@mail.gmail.com/

大致意思是 FOPEN_DIRECT_IO 在执行 parallel direct writes 优化的时候，要求文件不存在 page cache，这在 DIRECT_IO_ALLOW_MMAP 特性引入之前显然是成立的；但是在 DIRECT_IO_ALLOW_MMAP 引入之后，FOPEN_DIRECT_IO 文件就可以执行 mmap，在执行 mmap 之后文件就会有 page cache，从而与 parallel direct writes 优化相冲突


### iomode

为了解决上述 (FOPEN_DIRECT_IO) parallel direct writes 优化与 DIRECT_IO_ALLOW_MMAP 特性的冲突，v6.9 引入 iomode

本质上可以将以下操作分为 cached 与 uncached 两类：

| cached | uncached |
|--------|----------|
| non-FOPEN_DIRECT_IO open | FOPEN_DIRECT_IO+FOPEN_PARALLEL_DIRECT_WRITES open |
| (non-FOPEN_DIRECT_IO opened) mmap |  |
| (FOPEN_DIRECT_IO+DIRECT_IO_ALLOW_MMAP opened) mmap |  |

- non-FOPEN_DIRECT_IO open
    - open 及随后的 mmap 操作都会产生 page cache
- FOPEN_DIRECT_IO open
    - 如果带上了 FOPEN_PARALLEL_DIRECT_WRITES flag，那么 FOPEN_PARALLEL_DIRECT_WRITES 优化要求一定不能有 page cache
    - 如果带上了 DIRECT_IO_ALLOW_MMAP flag，那么 mmap 操作就会产生 page cache

所以在开启 FOPEN_DIRECT_IO+FOPEN_PARALLEL_DIRECT_WRITES 优化的时候，在 parallel direct writes 还存在 inflight IO 没有完成的时候：

- 不能再执行 non-FOPEN_DIRECT_IO open
- 或者执行 (FOPEN_DIRECT_IO+DIRECT_IO_ALLOW_MMAP opened) mmap

此时如果要执行上述两个操作，就需要睡眠等待所有 inflight parallel direct writes IO 完成之后，再继续执行以上两个操作


#### iocachectr

在 fuse_inode 中引入 iocachectr 计数，描述该文件 (inode) 处于 cache/uncache 状态的操作的实例数
- 初始值为 0
- 正数表示导致 cache 状态的操作的实例数（包括 non-FOPEN_DIRECT_IO open、(FOPEN_DIRECT_IO+DIRECT_IO_ALLOW_MMAP opened) mmap）
- 负数表示导致 uncache 状态的操作的实例数（包括 FOPEN_DIRECT_IO+FOPEN_PARALLEL_DIRECT_WRITES open）

```c
struct fuse_inode {
    /** Number of files/maps using page cache */
    int iocachectr;
    ...
}
```

```
 > 0 - caching io: files open in caching mode or mmap on direct_io file
 < 0 - parallel dio: direct io mode with parallel dio writes enabled
== 0 - direct io: no files open in caching mode and no files mmaped
```

同时 fi->state 增加一个状态位描述文件 (inode) 的 cache 状态，FUSE_I_CACHE_IO_MODE 状态被设置时，相当于 fi->iocachectr 计数为正数

```c
	/* Wants or already has page cache IO */
	FUSE_I_CACHE_IO_MODE,
```


上述介绍过 open(2)、mmap(2) 操作会增加 fi->iocachectr 计数，因而后面这些文件执行 close(2) 操作的时候需要执行相应的逆操作，即减回对应的 fi->iocachectr 计数，因而在 fuse_file 引入 iomode 字段描述该文件 (file) 当前是否持有对 fi->iocachectr 的计数
- IOM_NONE 为初始值
- IOM_CACHED 描述文件当前存在对 fi->iocachectr 的计数，例如 non-FOPEN_DIRECT_IO open 的时候增加了 fi->iocachectr 计数、或者 DIRECT_IO_ALLOW_MMAP mmap 的时候增加了 fi->iocachectr 计数，此时这些文件在 close(2) 的时候就必须减回对应的 fi->iocachectr 计数
- IOM_UNCACHED 则描述文件不存在 cache

```c
struct fuse_file {
	/** Does file hold a fi->iocachectr refcount? */
	enum { IOM_NONE, IOM_CACHED, IOM_UNCACHED } iomode;
	...
}
```



#### non-FOPEN_DIRECT_IO open

> open

non-FOPEN_DIRECT_IO 执行 open(2) 的时候，因为该操作会导致 cache，因而 fi->iocachectr 计数增加，ff->iomode 变为 IOM_CACHED 状态

```sh
# non-FOPEN_DIRECT_IO open
f_ops->open(), i.e. fuse_open
    fuse_open_common
        fuse_do_open
            fuse_file_open
                fuse_send_open // send FUSE_OPEN request
                ff->open_flags = outarg.open_flags;
        
        fuse_finish_open
            fuse_file_io_open
                # non-FOPEN_DIRECT_IO open (without FOPEN_DIRECT_IO) :
                fuse_file_cached_io_start
                    if (fi->iocachectr == 0)
                        set_bit(FUSE_I_CACHE_IO_MODE, &fi->state);
                    fi->iocachectr++
                    ff->iomode = IOM_CACHED
```

> mmap

执行 mmap(2) 的时候，因为之前 open(2) 的时候已经增加过 fi->iocachectr 计数和 ff->iomode 状态了，此时保持 fi->iocachectr 计数不变，ff->iomode 保持 IOM_CACHED 状态不变，相当于 non-FOPEN_DIRECT_IO 的时候，open(2)+mmap(2) 都复用同一份 fi->iocachectr 计数

```sh
fuse_file_mmap
    # fi->iocachectr untouched
    # ff->iomode untouched
```

> close

non-FOPEN_DIRECT_IO 打开的文件执行 close(2) 的时候，fi->iocachectr 计数增减小，ff->iomode 恢复为 IOM_NONE 状态

```
# close(2)
____fput
    fuse_release
        fuse_file_put(ff)
            # normally it's last put:
                fuse_file_io_release
                    case IOM_CACHED:
                        ff->iomode = IOM_NONE;
                        fi->iocachectr--;
                        if (fi->iocachectr == 0)
                            clear_bit(FUSE_I_CACHE_IO_MODE, &fi->state);
                            
                # send FUSE_RELEASE
                # free fuse_file (ff)
```


#### FOPEN_DIRECT_IO open

> open

FOPEN_DIRECT_IO 执行 open(2) 的时候，不会修改 fi->iocachectr 和 ff->iomode，保持默认值

```sh
# FOPEN_DIRECT_IO open
f_ops->open(), i.e. fuse_open
    fuse_open_common
        fuse_do_open
            fuse_file_open
                fuse_send_open // send FUSE_OPEN request
                ff->open_flags = outarg.open_flags;
        
        fuse_finish_open
            fuse_file_io_open
                # FOPEN_DIRECT_IO open (with FOPEN_DIRECT_IO):
                fi->iocachectr untouched (initial value 0)
                ff->iomode untouched (initial value IOM_NONE)
                return
```

> write

执行 write(2) 的时候，由于没有开启 FOPEN_PARALLEL_DIRECT_WRITES 优化，此时 write(2) 操作就是持有 inode lock 锁的

```sh
f_op->write_iter(), i.e. fuse_file_write_iter()
    fuse_direct_write_iter
        fuse_dio_lock
            # exclusive lock (since FOPEN_PARALLEL_DIRECT_WRITES not enabled)
            inode_lock(inode)
        
        # process direct writes
        
        fuse_dio_unlock
```


> close

FOPEN_DIRECT_IO 打开的文件执行 close(2) 的时候，如果没有 DIRECT_IO_ALLOW_MMAP，也没有 FOPEN_PARALLEL_DIRECT_WRITES 优化，那么 ff->iomode 就还是默认值 IOM_NONE，相当于当前这个打开的文件 (file) 对 iomode 没有任何影响 (既不会产生 cache，又不依赖 uncache)，因而当前这个文件 close(2) 的时候也就不需要执行任何清理操作

```
# close(2)
____fput
    fuse_release
        fuse_file_put(ff)
            # normally it's last put:
                fuse_file_io_release
                    case IOM_NONE:
                        # Nothing to do
                            
                # send FUSE_RELEASE
                # free fuse_file (ff)
```


#### FOPEN_DIRECT_IO|FOPEN_PARALLEL_DIRECT_WRITES open

> open

FOPEN_DIRECT_IO|FOPEN_PARALLEL_DIRECT_WRITES 执行 open(2) 的时候，与之前一样不会修改 fi->iocachectr 和 ff->iomode，保持默认值，因为虽然设置了 FOPEN_PARALLEL_DIRECT_WRITES，但是当前 open 操作还没有明确依赖 uncache，后面在执行 write(2) 操作开启 FOPEN_PARALLEL_DIRECT_WRITES 优化下发多个 parallel direct writes IO 的时候，才会设置 fi->iocachectr 和 ff->iomode

```sh
# FOPEN_DIRECT_IO open
f_ops->open(), i.e. fuse_open
    fuse_open_common
        fuse_do_open
            fuse_file_open
                fuse_send_open // send FUSE_OPEN request
                ff->open_flags = outarg.open_flags;
        
        fuse_finish_open
            fuse_file_io_open
                # FOPEN_DIRECT_IO open (with FOPEN_DIRECT_IO):
                fi->iocachectr untouched (initial value 0)
                ff->iomode untouched (initial value IOM_NONE)
                return
```

> write

FOPEN_DIRECT_IO|FOPEN_PARALLEL_DIRECT_WRITES 打开的文件执行 write(2) 的时候，就会开启 parallel direct writes 优化，此时在下发 write IO 的时候就是持有 shared lock 的，同时会对下发 write IO 的这段时间（从开始下发 IO 到 IO 下发完成为止，不需要等待 IO 完成）开启 uncached 保护，即下发 IO 的时候减小 fi->iocachectr 计数，IO 下发完成（不需要等待 IO 完成）的时候加回 fi->iocachectr 计数

因为这里 fi->iocachectr 计数的减去和增加操作都是成对的，不需要到 close(2) 的时候再执行相应的逆操作，因而这里也就不需要设置 ff->iomode 状态

```sh
f_op->write_iter(), i.e. fuse_file_write_iter()
    fuse_direct_write_iter
        fuse_dio_lock
            # shared lock (since FOPEN_PARALLEL_DIRECT_WRITES enabled)
            inode_lock_shared(inode)
            
            fuse_inode_uncached_io_start
                fi->iocachectr--
        
        # process direct writes
            # send parallel direct writes IOs
        
        fuse_dio_unlock
            fuse_inode_uncached_io_end
                fi->iocachectr++
            inode_unlock_shared(inode)
```

> close

FOPEN_DIRECT_IO|FOPEN_PARALLEL_DIRECT_WRITES 打开的文件执行 close(2) 的时候，如果没有 DIRECT_IO_ALLOW_MMAP，那么 ff->iomode 就还是默认值 IOM_NONE，此时当前文件 close(2) 的时候也就不需要执行任何清理操作

```
# close(2)
____fput
    fuse_release
        fuse_file_put(ff)
            # normally it's last put:
                fuse_file_io_release
                    case IOM_NONE:
                        # Nothing to do
                            
                # send FUSE_RELEASE
                # free fuse_file (ff)
```


#### FOPEN_DIRECT_IO|DIRECT_IO_ALLOW_MMAP open

> open

执行 open(2) 的时候，与之前一样不会修改 fi->iocachectr 和 ff->iomode，保持默认值，因为虽然设置了 DIRECT_IO_ALLOW_MMAP，但是当前 open 操作还没有明确依赖 cache，后面在执行 mmap(2) 操作的时候，才会设置 fi->iocachectr 和 ff->iomode

```sh
# FOPEN_DIRECT_IO open
f_ops->open(), i.e. fuse_open
    fuse_open_common
        fuse_do_open
            fuse_file_open
                fuse_send_open // send FUSE_OPEN request
                ff->open_flags = outarg.open_flags;
        
        fuse_finish_open
            fuse_file_io_open
                # FOPEN_DIRECT_IO open (with FOPEN_DIRECT_IO):
                fi->iocachectr untouched (initial value 0)
                ff->iomode untouched (initial value IOM_NONE)
                return
```

> mmap

执行 DIRECT_IO_ALLOW_MMAP mmap(2) 的时候，因为该操作会导致 cache，因而 fi->iocachectr 计数增加，ff->iomode 变为 IOM_CACHED 状态

```sh
fuse_file_mmap
    # (FOPEN_DIRECT_IO|DIRECT_IO_ALLOW_MMAP) opened mmap:
    # and vma->vm_flags & VM_MAYSHARE (it's a shareable mmap):
        fuse_file_cached_io_open
            if (fi->iocachectr == 0)
                set_bit(FUSE_I_CACHE_IO_MODE, &fi->state);
            fi->iocachectr++
            ff->iomode = IOM_CACHED
```


> write

执行 write(2) 的时候，由于没有开启 FOPEN_PARALLEL_DIRECT_WRITES 优化，此时 write(2) 操作就是持有 inode lock 锁的

```sh
f_op->write_iter(), i.e. fuse_file_write_iter()
    fuse_direct_write_iter
        fuse_dio_lock
            # exclusive lock (since FOPEN_PARALLEL_DIRECT_WRITES not enabled)
            inode_lock(inode)
        
        # process direct writes
        fuse_direct_io
            # flush all page cache prior DIRECT write IO (since DIRECT_IO_ALLOW_MMAP enabled)
            filemap_write_and_wait_range
            
            # send DIRECT write IO
        
        fuse_dio_unlock
```


> close

执行 close(2) 的时候，如果之前有执行过 DIRECT_IO_ALLOW_MMAP mmap(2) 操作，那么 ff->iomode 就是 IOM_CACHED，此时当前文件 close(2) 的时候，fi->iocachectr 计数减小，ff->iomode 恢复为 IOM_NONE 状态

```
# close(2)
____fput
    fuse_release
        fuse_file_put(ff)
            # normally it's last put:
                fuse_file_io_release
                    case IOM_CACHED:
                        fuse_file_cached_io_release
                            ff->iomode = IOM_NONE;
                            fi->iocachectr--;
                            if (fi->iocachectr == 0)
                                clear_bit(FUSE_I_CACHE_IO_MODE, &fi->state);
                            
                # send FUSE_RELEASE
                # free fuse_file (ff)
```



#### FOPEN_DIRECT_IO|DIRECT_IO_ALLOW_MMAP|FOPEN_PARALLEL_DIRECT_WRITES open

当同时开启 DIRECT_IO_ALLOW_MMAP|FOPEN_PARALLEL_DIRECT_WRITES 的时候，DIRECT_IO_ALLOW_MMAP 会产生 page cache，而 FOPEN_PARALLEL_DIRECT_WRITES 优化又依赖文件不能有 page cache，因而两者不能同时存在，此时这两者共存的规则是：

> Instead of denying caching mode on parallel dio open, deny caching open only while parallel dio are in-progress and wait for in-progress parallel dio writes before entering inode caching io mode.

> This allows executing parallel dio when inode is not in caching mode even if shared mmap is allowed, but no mmaps have been performed on the inode in question.

> An mmap on direct_io file now waits for all in-progress parallel dio writes to complete, so parallel dio writes together with FUSE_DIRECT_IO_ALLOW_MMAP is enabled by this commit.

即

- parallel direct writes 执行过程中，如果要做 DIRECT_IO_ALLOW_MMAP mmap，就必须等待所有 parallel direct writes 下发完成后（退出 uncache 状态后），才能继续执行 mmap
- 执行 DIRECT_IO_ALLOW_MMAP mmap 之后，parallel direct writes 优化就默认关闭，此时 write 操作必须持有 inode lock 锁；等到执行 DIRECT_IO_ALLOW_MMAP mmap 的文件 close、以及 unmap 之后，即文件退出 cache 状态之后，write 操作才会重新开启 parallel direct writes 优化


> open

执行 open(2) 的时候，与之前一样不会修改 fi->iocachectr 和 ff->iomode，保持默认值

```sh
# FOPEN_DIRECT_IO open
f_ops->open(), i.e. fuse_open
    fuse_open_common
        fuse_do_open
            fuse_file_open
                fuse_send_open // send FUSE_OPEN request
                ff->open_flags = outarg.open_flags;
        
        fuse_finish_open
            fuse_file_io_open
                # FOPEN_DIRECT_IO open (with FOPEN_DIRECT_IO):
                fi->iocachectr untouched (initial value 0)
                ff->iomode untouched (initial value IOM_NONE)
                return
```



> mmap

执行 DIRECT_IO_ALLOW_MMAP mmap(2) 的时候，如果当前 fi->iocachectr 计数为负数，即当前正在下发 parallel direct writes IO，即当前文件处于 uncache 状态，那么当前 mmap 操作需要在 fi->direct_io_waitq 等待队列等待，等待当前正在执行的 parallel direct writes IO 下发完成，即等待 fi->iocachectr 计数恢复为大于等于 0

```sh
fuse_file_mmap
    # (FOPEN_DIRECT_IO|DIRECT_IO_ALLOW_MMAP) opened mmap:
    # and vma->vm_flags & VM_MAYSHARE (it's a shareable mmap):
        fuse_file_cached_io_open
            if fi->iocachectr < 0, i.e. inode is in uncached state:
                # Setting the bit advises new direct-io writes to use an exclusive
                # lock - without it the wait below might be forever.
                set_bit(FUSE_I_CACHE_IO_MODE, &fi->state)
                
                # wait until inode exits uncached state
                wait_event(fi->direct_io_waitq, fi->iocachectr) >= 0)
                
            
            if (fi->iocachectr == 0)
                set_bit(FUSE_I_CACHE_IO_MODE, &fi->state);
            fi->iocachectr++
            ff->iomode = IOM_CACHED
```


> write: disable parallel direct writes when DIRECT_IO_ALLOW_MMAP mmap

执行 write(2) 的时候，如果 fi->state 的 FUSE_I_CACHE_IO_MODE 状态被设置，说明该文件此前已经执行过 DIRECT_IO_ALLOW_MMAP mmap，即该 inode 当前处于 cached 状态；那么此时就默认关闭 parallel direct writes 优化，即此时 write 操作都是持有 exclusive inode lock 锁的

```sh
f_op->write_iter(), i.e. fuse_file_write_iter()
    fuse_direct_write_iter
        fuse_dio_lock
            # exclusive lock (since FUSE_I_CACHE_IO_MODE is set in &fi->state)
            inode_lock(inode)
        
        # process direct writes
        fuse_direct_io
            # flush all page cache prior DIRECT write IO (since DIRECT_IO_ALLOW_MMAP enabled)
            filemap_write_and_wait_range
            
            # send DIRECT write IO
        
        fuse_dio_unlock
```

> close+unmap

后面执行 DIRECT_IO_ALLOW_MMAP mmap 的文件 close(2) 以及 unmap 的时候，由于之前有执行过 DIRECT_IO_ALLOW_MMAP mmap(2) 操作，那么 ff->iomode 就是 IOM_CACHED，此时文件 close(2) 或者 unmap 的时候，fi->iocachectr 计数减小，ff->iomode 恢复为 IOM_NONE 状态

```
# close(2)
____fput
    fuse_release
        fuse_file_put(ff)
            # normally it's last put:
                fuse_file_io_release
                    case IOM_CACHED:
                        fuse_file_cached_io_release
                            ff->iomode = IOM_NONE;
                            fi->iocachectr--;
                            if (fi->iocachectr == 0)
                                clear_bit(FUSE_I_CACHE_IO_MODE, &fi->state);
                            
                # send FUSE_RELEASE
                # free fuse_file (ff)
```

> write: enable parallel direct writes when DIRECT_IO_ALLOW_MMAP mmap exits

后面等到 DIRECT_IO_ALLOW_MMAP mmap 的文件 close(2) 以及 unmap 之后，inode 退出 cached 状态，之后再执行 write 操作的时候，就会重新恢复 parallel direct writes 优化，此时下发 write IO 的时候就只是持有 shared lock 锁


```sh
f_op->write_iter(), i.e. fuse_file_write_iter()
    fuse_direct_write_iter
        fuse_dio_lock
            # shared lock (since FOPEN_PARALLEL_DIRECT_WRITES enabledm, and FUSE_I_CACHE_IO_MODE state exits)
            inode_lock_shared(inode)
            
            fuse_inode_uncached_io_start
                fi->iocachectr--
        
        # process direct writes
            # send parallel direct writes IOs
        
        fuse_dio_unlock
            fuse_inode_uncached_io_end
                fi->iocachectr++
            inode_unlock_shared(inode)
```
